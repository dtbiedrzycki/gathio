# Dependency Security Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the production-reachable vulnerabilities surfaced by `pnpm audit` without touching `mongoose` (separate migration, out of scope) or dev-only tooling (`eslint`, `cypress`, `nodemon`, `jscodeshift` — never ship).

**Architecture:** Each task bumps one logical group of dependencies (direct `package.json` version bump, or a `pnpm.overrides` entry for a transitive-only package), reinstalls, rebuilds, and runs the Cypress suite before committing. Grouping by package keeps each commit's diff reviewable and bisectable if a bump breaks something.

**Tech Stack:** pnpm, TypeScript (`tsc`), Cypress e2e, no unit test runner.

**Spec:** This plan implements the findings from the security review in this conversation (no separate spec doc — the audit output and version-range table are reproduced in Global Constraints below, sourced from `pnpm audit --json` run 2026-08-20 against `package.json`/`pnpm-lock.yaml` on `feat/mad-customizations`).

## Global Constraints

- Sandbox note: the default pnpm store (`~/.local/share/pnpm/store`) is not writable in this environment. Every `pnpm install` / `pnpm update` in this plan MUST pass `--store-dir="$TMPDIR/pnpm-store"` (or export `PNPM_STORE_DIR="$TMPDIR/pnpm-store"` once per shell) or it will fail with `ERR_SQLITE_ERROR`.
- Do not touch `mongoose` (stays at `^5.13.22`) — the fix requires a 5→6 major migration, tracked separately.
- Do not touch dev-only packages surfaced by the audit (`eslint`/`minimatch`/`brace-expansion`/`js-yaml`/`flatted` chain, `cypress`/`extract-zip`/`tmp`/`cross-spawn`, `jscodeshift`/`@babel/core`, `nodemon`/`semver`, `picomatch`) — never bundled into `dist/`, not urgent.
- Target versions (from `pnpm audit` patched-version ranges, captured 2026-08-20):
  - `handlebars` → `^4.7.9`
  - `i18next-fs-backend` → `^2.6.6`
  - `i18next-http-middleware` → `^3.9.7`
  - `dompurify` → `^3.4.13` (and matching `@types/dompurify` bump if one exists)
  - `sanitize-html` → `^2.17.5`
  - `nanoid` → `^5.1.16` (direct dep only — the transitive `nanoid@3.3.7` via `sanitize-html>postcss` is fixed by the `postcss` override below)
  - `express` → `^4.21.2` (or latest 4.x — resolves `path-to-regexp`/`body-parser`/`qs` transitively)
  - `nodemailer` → latest `6.9.x` patch if one exists covering the `raw`-option bypass; otherwise document the gap (do not jump to `7.x`/`8.x`/`9.x` without checking for breaking API changes first)
  - `@sendgrid/mail` → `^8.1.6` (matches the already-pinned `@sendgrid/helpers@^8.0.0` — the repo's `package.json` currently has these two mismatched at major versions 6 and 8, which is itself worth fixing; `@sendgrid/mail@8.x`'s `@sendgrid/client` uses `axios` instead of the deprecated `request` package, eliminating that whole vulnerable subtree — `form-data@2.x`, `tough-cookie`, `qs`, `har-validator`/`ajv` — for the sendgrid path entirely)
  - `pnpm.overrides`: `form-data@^4.0.6`, `axios@^1.18.0`, `postcss@^8.5.18` (also fixes the transitive `nanoid` copy under `sanitize-html>postcss`), `ts-deepmerge@^8.0.0`, `tough-cookie@^4.1.3`, `phin@^3.7.1` (the last two cover the copies still pulled in via `ical>request`, since `ical` itself has no maintained release — see the accepted-risk note below)
- **Accepted risk, explicitly out of scope:** the `request` package itself (pulled in via `ical>request`) has a moderate SSRF advisory with no real fix — its last published version is `2.88.2` and the advisory's claimed `>=2.88.3` patched floor was never released (confirmed via `pnpm view request versions`). `ical` (the calendar-import feature) is unmaintained and hasn't dropped `request`. This plan does not attempt to override `request` itself. Task 8's audit re-check must expect this one moderate finding to remain, scoped only to `ical`'s import path, and Task 9's PR description must call it out by name so it isn't mistaken for an oversight.
- After every task: `pnpm install --store-dir="$TMPDIR/pnpm-store"`, `pnpm build`, `pnpm lint`, then the targeted `pnpm audit` re-check for that package (`pnpm audit --json | grep -A2 '"module_name": "<pkg>"'` or equivalent) before committing.
- Full Cypress suite (`pnpm test`) runs once at the end (Task 9), not after every task — it's the slow, expensive check; per-task `pnpm build`/`pnpm lint` catch type/lint breakage cheaply in between.

### Task 8: Re-run the full `pnpm audit` and confirm the remaining findings are only `mongoose`, `ical>request`, and dev-only

**Files:**

- None modified — verification-only task.

**Interfaces:**

- Consumes: the cumulative state of `package.json`/`pnpm-lock.yaml` from Tasks 1–7.
- Produces: the final findings list for the PR description in Task 9.

- [ ] **Step 1: Run the full audit**

```bash
pnpm audit --json --store-dir="$TMPDIR/pnpm-store" 2>&1 > "$TMPDIR/audit-final.json"
python3 -c "
import json
d = json.load(open('$TMPDIR/audit-final.json'))
advs = d.get('advisories', {})
order = {'critical':0,'high':1,'moderate':2,'low':3}
rows = []
for k,v in advs.items():
    dev = any(f.get('dev') for f in v.get('findings',[]))
    rows.append((v.get('severity'), v.get('module_name'), dev, v.get('title')))
rows.sort(key=lambda r: order.get(r[0],4))
for sev,mod,dev,title in rows:
    print(f'[{sev.upper()}]{\" (dev)\" if dev else \"\"} {mod}: {title}')
print()
print(d.get('metadata'))
"
```

- [ ] **Step 2: Verify the remaining list**
